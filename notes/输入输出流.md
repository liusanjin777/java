# 输入输出流（字节流）

- 日期：2026-08-21
- 阶段：Java 基础
- 状态：新学

## 学习目标

- 理解什么是流（Stream）以及字节流和字符流的区别
- 掌握 `FileInputStream` 的三种读取方式
- 掌握 `FileOutputStream` 的写入方式
- 能编写一个简单的文件复制程序

## 核心概念

### 什么是流

流（Stream）是把数据当作一种「序列」来读写的方式，就像水管里的水，从一个地方流向另一个地方。Java 的 `java.io` 包把输入输出都抽象成流：

- 输入流（`InputStream`）：程序从「源」读数据
- 输出流（`OutputStream`）：程序把数据写到「目标」

### 字节流与字符流

以字节为单位读写的流叫字节流，顶层抽象是 `InputStream` / `OutputStream`。它们适合处理图片、音视频、压缩包等二进制数据，也能处理文本。因为字符本身在底层也是一串字节，用字节流读文本后再按编码解释即可。

### FileInputStream 的三种读取方式

`FileInputStream` 从文件读字节，常用三个 `read` 方法：

| 方法 | 作用 | 返回值 |
| --- | --- | --- |
| `int read()` | 读一个字节，转成 `int`（0~255） | 读到字节的 int 值，读到末尾返回 -1 |
| `int read(byte[] b)` | 尽量把缓冲区 `b` 装满，最多读 `b.length` 个字节 | 实际读到的字节数，读到末尾返回 -1 |
| `int read(byte[] b, int off, int len)` | 从 `b[off]` 开始读，最多 `len` 个字节 | 实际读到的字节数，读到末尾返回 -1 |

重点：`read(byte[])` 返回的是一次**实际读到的字节数**，而不是 `byte[]` 里有什么内容，更不等于缓冲区长度。最后一次读不满缓冲区时，要用返回值控制处理范围。

### FileOutputStream

`FileOutputStream` 向文件写字节。构造时如果文件不存在会自动创建；默认覆盖原内容。常用写法：

```java
FileOutputStream file = new FileOutputStream("assets/demo_output.txt");
file.write("Hello World".getBytes());  // 写入字节数组
file.close();
```

### 关闭资源

流用完后要 `close()` 释放系统资源。`try-with-resources` 语法可以自动关闭：

```java
try (
    FileInputStream fInput = new FileInputStream("assets/demo.txt");
    FileOutputStream fOutput = new FileOutputStream("assets/demo_output.txt");
) {
    // 读和写
} catch (Exception e) {
    System.out.println("Error: " + e.getMessage());
}
```

## 代码示例

示例代码在 `JavaBaseUse/Stream/` 下，包名为 `JavaBaseUse.Stream`，数据文件在项目根目录的 `assets/` 下。编译运行前先在项目根目录创建 `assets/demo.txt`。

### 单个字节读取：StreamDemoA

`InputStream.java` 里的 `StreamDemoA` 一次读一个字节，`read()` 返回的是字节的 int 值，例如 ASCII 字符 `a` 是 97：

```java
FileInputStream file = new FileInputStream("assets/demo.txt");
int data;
while ((data = file.read()) != -1) {
    System.out.println("data=" + data);   // a=97, b=98, c=99 ...
}
file.close();
```

### 缓冲区读取：StreamDemoB

`StreamDemoB` 用 `byte[2]` 当缓冲区，一次读 2 个字节，打印第二次 `read` 实际读到的字节数：

```java
byte[] data = new byte[2];
file.read(data);
System.out.println("data=" + file.read(data));  // 第二次读仍能读到 2 个字节，输出 data=2
file.close();
```

### 指定偏移读取：StreamDemoC

`StreamDemoC` 用 `read(byte[], off, len)` 指定从偏移 0 开始只读 1 个字节：

```java
byte[] data = new byte[2];
System.out.println("data=" + file.read(data, 0, 1));  // 实际读到 1 个字节，输出 data=1
file.close();
```

### 写入文件：OutputStream

`OutputStream.java` 用字符串转字节数组写文件：

```java
FileOutputStream file = new FileOutputStream("assets/demo_output.txt");
file.write("Hello World".getBytes());
file.close();
```

### 复制文件：Stream

`Stream.java` 把一个文件一个字节一个字节地复制到另一个文件，用 `-1` 判断是否读完：

```java
try (
    FileInputStream fInput = new FileInputStream("assets/demo.txt");
    FileOutputStream fOutput = new FileOutputStream("assets/demo_output.txt");
) {
    int data;
    while ((data = fInput.read()) != -1) {
        fOutput.write(data);
    }
} catch (Exception e) {
    System.out.println("Error: " + e.getMessage());
}
```

编译运行：

```bash
javac -d out JavaBaseUse/Stream/*.java
java -cp out JavaBaseUse.Stream.InputStream
java -cp out JavaBaseUse.Stream.OutputStream
java -cp out JavaBaseUse.Stream.Stream
```

`InputStream` 的运行结果：`StreamDemoA` 打印一串字节的 int 值（97、98、99……），`StreamDemoB` 打印 `data=2`，`StreamDemoC` 打印 `data=1`。`Stream` 运行后会把 `demo.txt` 的内容复制到 `demo_output.txt`。

## 易错点

- 相对路径以「当前工作目录」为基准，不是源码文件所在目录。从项目根目录运行时要写成 `assets/demo.txt`
- `read(byte[])` 的返回值是实际读到的字节数，不是缓冲区大小，也不是内容本身
- 文件读到末尾后 `read` 返回 -1，循环条件要写成 `!= -1`
- `read(byte[])` 最后一次可能读不满缓冲区，处理时要用返回值 `count` 控制，别把缓冲区没填满的位置也当有效数据
- 流用完后要 `close()`；用 try-with-resources 能自动关闭，避免资源泄漏
- `FileOutputStream` 默认覆盖文件内容，追加内容需要传 `true`（`new FileOutputStream(path, true)`）
- 用字节流直接按字符打印中文可能乱码，因为一个中文字符占多个字节，需要用字符流或按编码解码

## 练习与思考

1. 用 `byte[2]` 做缓冲区，改写 `Stream` 的复制程序，复制 `demo.txt` 到 `copy.txt`，体会批量读写的效率和写法区别
2. 思考：`read()` 返回 `int` 而不是 `byte`，为什么？
3. 试着修改 `StreamDemoB`，把两次 `read` 都保留，观察第一次和第二次分别读到了什么
4. 用 `FileOutputStream` 以追加模式写两次内容，看看文件里是不是两段内容都有
5. 读一段文本后打印，看看中文会不会乱码，思考怎么解决

## 小结

- 输入流负责读，输出流负责写，都以字节为单位处理数据
- `read()` 一次读一个字节并转成 int，`read(byte[])` 批量读取并返回实际字节数
- 相对路径依赖于运行时的当前工作目录
- 用完要关闭流，try-with-resources 是更省心的写法
