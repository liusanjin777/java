# 基本类型和引用类型

- 日期：2026-08-21
- 阶段：Java 基础
- 状态：新学

## 学习目标

- 认识 Java 的 8 种基本类型及其取值范围
- 区分基本类型和引用类型的内存与赋值行为
- 理解引用类型的 `null`、`==` 与 `equals` 的区别
- 掌握方法传参时"按值传递"的真正含义

## 核心概念

### 基本类型（Primitive Type）

基本类型直接保存具体的值，共 8 种：整数 4 种、浮点 2 种、字符 1 种、布尔 1 种。它们的大小固定，不依赖具体机器：

| 类型 | 大小 | 默认值 | 取值范围示例 |
| --- | --- | --- | --- |
| `byte` | 1 字节 | 0 | -128 ~ 127 |
| `short` | 2 字节 | 0 | -32768 ~ 32767 |
| `int` | 4 字节 | 0 | 约 ±21 亿 |
| `long` | 8 字节 | 0 | 很大，字面量末尾写 `L` |
| `float` | 4 字节 | 0.0 | 字面量末尾写 `f` |
| `double` | 8 字节 | 0.0 | Java 默认浮点类型 |
| `char` | 2 字节 | '\u0000' | 单个字符，用单引号 |
| `boolean` | 不固定 | false | 只有 `true` / `false` |

基本类型的变量存的是值本身，赋值时复制值，两个变量互不影响。

### 引用类型（Reference Type）

引用类型包括类（如 `String`、自定义类）、接口、数组、枚举等。引用类型的变量存的是对象的引用（可以理解成地址），不是对象本身。同一个对象可以被多个引用指向，通过一个引用修改对象，另一个引用也能看到。

引用类型变量未赋值时默认是 `null`，表示不指向任何对象。

### 包装类

每种基本类型都有对应的包装类：`Byte`、`Short`、`Integer`、`Long`、`Float`、`Double`、`Character`、`Boolean`。包装类属于引用类型，常用来获取类型的大小和范围。Java 会自动在基本类型和包装类之间转换（自动装箱 / 拆箱）。

### `==` 与 `equals`

- 对基本类型，`==` 比较的是值
- 对引用类型，`==` 比较的是两个引用是否指向同一个对象，不是内容
- 要比较对象内容用 `equals`，例如 `String` 的 `equals`

### 方法传参：按值传递

Java 方法传参都是按值传递：

- 传基本类型时，传递的是值的副本，方法内改参数不影响原来的变量
- 传引用类型时，传递的是引用值的副本，副本仍指向同一个对象，所以方法内可以修改对象的属性，但重新给参数赋值不会影响外部引用

## 代码示例

示例代码在 `基础概念/基本类型和引用类型/` 下，包名为 `basic.types`。

### 8 种基本类型

`PrimitiveDemo.java` 声明了全部 8 种基本类型，并通过包装类打印大小和范围：

```java
package basic.types;

public class PrimitiveDemo {
    public static void main(String[] args) {
        byte byteValue = 127;
        short shortValue = 32000;
        int intValue = 2000000000;
        long longValue = 9000000000L;   // long 字面量末尾要写 L

        float floatValue = 3.14f;       // float 字面量末尾要写 f
        double doubleValue = 3.141592653589793;

        char charValue = 'A';
        boolean boolValue = true;
        // ... 打印上面的变量
        showSize();
    }

    static void showSize() {
        System.out.println("byte 大小=" + Byte.BYTES + " 字节，范围 "
                + Byte.MIN_VALUE + " ~ " + Byte.MAX_VALUE);
        // short / int / long / float / double / char 同理
    }
}
```

### 引用类型的行为

`ReferenceDemo.java` 演示数组、`String` 和自定义类。两个引用指向同一个数组时，改其中一个就能看到变化；`==` 比较引用是否相同，`equals` 比较内容：

```java
String name = null;                 // 引用类型默认是 null
int[] a = {1, 2, 3};
int[] b = a;                        // b 和 a 指向同一个数组
b[0] = 100;                         // a[0] 也会变成 100

String s1 = new String("hello");
String s2 = new String("hello");
System.out.println(s1 == s2);       // false，不是同一个对象
System.out.println(s1.equals(s2));  // true，内容相同
```

`PassByValueDemo.java` 展示方法传参：基本类型在方法里改参数不影响外面，引用类型的引用副本可以修改同一个对象的属性：

```java
int num = 5;
changePrimitive(num);               // 方法内改成 100，外面 num 仍是 5

Person person = new Person("小林");
changeReference(person);            // 方法内改名，外面 person.name 也变了
```

编译并运行：

```bash
javac -d out 基础概念/基本类型和引用类型/*.java
java -cp out basic.types.PrimitiveDemo
java -cp out basic.types.ReferenceDemo
java -cp out basic.types.PassByValueDemo
```

## 易错点

- `long` 字面量末尾忘写 `L`，`float` 字面量末尾忘写 `f`，可能编译报错或精度丢失
- 用 `==` 比较两个 `String` 内容会出错，应该用 `equals`
- 把两个引用变量互相赋值，是让它们指向同一个对象，不是复制对象
- 引用类型变量不初始化就使用会得到 `null`，调用方法会抛 `NullPointerException`
- 认为"引用传递"能改变外部变量指向，实际上引用也只是按值传递
- 基本类型转大范围类型自动提升，往小范围转可能溢出，例如把 `int` 直接赋给 `byte` 会编译报错

## 练习与思考

1. 试着写一个方法，参数是 `int` 数组，在方法里把数组第 1 个元素改成 99，观察调用方的数组是否变化，为什么？
2. 思考：`Integer` 是引用类型，为什么 `==` 比较两个 `new Integer(1)` 会是 `false`？
3. 计算 `byte`、`short`、`int`、`long` 各能表示的整数范围，体会为什么大数要用 `long`。
4. 把一个对象作为参数传给方法，方法里执行 `p = new Person("新对象")`，外部引用会不会改变？验证你的答案。
5. 例如 `System.out.println`，想一想：传 `num`（基本类型）和传 `person`（引用类型）时，方法里分别能做什么改变？

## 小结

- 8 种基本类型直接存值，引用类型存对象的引用
- 基本类型赋值复制值，引用类型赋值复制引用，可能共享对象
- 比较内容用 `equals`，`==` 对引用类型比较的是否是同一个对象
- Java 方法传参按值传递：基本类型传副本，引用类型传引用副本
